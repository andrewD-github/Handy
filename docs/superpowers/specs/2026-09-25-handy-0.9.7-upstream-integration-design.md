# Handy v0.9.7 upstream integration design

Date: 2026-09-25
Status: approved by the user's direction to integrate v0.9.7 bug fixes

## Objective

Upgrade the customized portable Handy installation from the verified v0.9.6 base to official upstream tag `v0.9.7` (`05e0aedd2906f0d82722735f930465950c476b90`) without losing direct-in-prompt streaming, optional refocus resume, diagnostics/replay support, the portable-data boundary, or the custom token theme.

## Chosen approach

Merge the complete official v0.9.7 tag into `codex/handy-progressive-dictation`, then resolve only the documented customization boundary. Do not cherry-pick a hand-selected subset of fixes and do not restore old v0.9.6 upstream-owned audio, transcription, settings, or UI implementations over v0.9.7.

This preserves the dependency relationships among the 31 upstream commits, including tail-audio capture, the real-time-safe microphone callback, shortcut parity, model-file recovery, Windows overlay scaling, WebView accelerator-key handling, and transcribe-cpp 0.2.3.

## Ownership boundary

Upstream v0.9.7 owns audio capture, resampling, VAD backends, shortcut coordination, inference/model lifecycle, overlay rendering, model recovery, translations, release metadata, and normal settings/UI evolution.

The custom branch continues to own only:

- append-only direct-prompt policy and target/refocus state in `progressive_dictation.rs`;
- narrow lifecycle calls and streaming snapshot publication at upstream hook points;
- guarded native target capture and serialized append operations;
- the direct-prompt output and refocus-resume settings plus their Advanced UI controls;
- diagnostic/replay instrumentation that does not change production inference policy;
- the blue presentation through upstream theme tokens;
- portable transactional install and rollback tooling.

Where v0.9.7 and the customization touch the same file, retain the complete v0.9.7 behavior first and then adapt the smallest custom hook to the new API or control flow.

## Integration flow

1. Fetch and verify the official `v0.9.7` tag and commit identity.
2. Create an isolated integration worktree/branch from the current clean customized head.
3. Merge the complete tag and inventory textual and semantic conflicts against `docs/upstream-integration.md`.
4. Resolve conflicts by preserving upstream implementations and reconnecting the custom extension points.
5. Update version-pinned documentation, candidate paths, runtime hashes, and installer defaults for v0.9.7.
6. Regenerate bindings and run formatting, translation, frontend, Rust, replay-tool, and installer/rollback tests.
7. Build an optimized replay executable and replay the frozen 17-session actual-use cohort in simulated real time on the selected accelerator.
8. Build a proper production-packaged portable candidate, verify the isolated app, create a release report, and transactionally replace `D:\Apps\Handy` only if all gates pass.
9. Verify the installed executable, process, settings, selected model, history preservation, startup logs, direct-prompt/refocus behavior, and rollback manifest.

## Acceptance gates

- The full upstream v0.9.7 tag is present in branch history.
- All custom direct-prompt and refocus tests pass without weakening v0.9.7 tests.
- Frontend build, lint, translations, Rust tests, replay-tool tests, and rollback validation pass.
- All 17 frozen real-use recordings complete with zero visible retractions/backspaces.
- p95 first-visible text remains below 3,000 ms, p95 maximum update gap below 4,000 ms, and p95 stop-to-final below 1,000 ms.
- No final disagreement exceeds four token edits and p95 final appended/different text remains at most five token edits.
- No WER/CER claim is made without a trustworthy reference transcript.
- `D:\Apps\Handy\Data` is preserved; `history.db` is unchanged across installation.
- Direct-prompt output, Nemotron Streaming 3.5, and refocus resume remain enabled after restart.
- A timestamped, hash-verified rollback backup can restore the preceding v0.9.6 installation.

## Failure handling

Merge or test failures are fixed in the isolated integration tree and never against the installed daily driver. Replay or live-candidate gate failure blocks installation. Any installed-surface failure triggers restoration from the new timestamped backup while leaving `Data` untouched.

## Accepted limitation

The previously accepted WebView limitation remains: when refocus resume is enabled, a Chromium/WebView prompt that reuses the same native focused control after Submit can receive pending text when focus returns. The setting remains explicit and defaults off in upstream-derived configurations, while the user's installation keeps it enabled.
